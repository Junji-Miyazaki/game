# BIRDS RECLAIM — MIRROR 作業ログ

BIRDS RECLAIM（`../birds-reclaim/`）から派生した映像インスタレーションの試作。カメラに映った人物を「塔」に見立て、鳥がその輪郭をついばむ。フォルダ名 `birds-reclaim-mirror` は仮。

## 2026-11-11 試作 v0（Fable 5.2）

### 結論
- Mac とカメラとブラウザだけで動く形にできた。`index.html` 1枚（577 行）。
- 合成の人影と実写の写真で、鳥が来る・ついばむ・増える・払うと離れて戻る・人が去ると去る、までを確かめた。
- 本物のカメラでの動作は、こちらでは確かめられなかった（作業に使ったアプリ内ブラウザはカメラを使えない）。同じ日にユーザーが Chrome で開き、「動いた」と確認した（下の「ユーザーの確認」）。

### 決めたこと
| 項目 | 内容 |
|---|---|
| 人物の切り出し | MediaPipe Tasks Vision の ImageSegmenter ＋ Selfie Segmentation の横長モデル（入力 256×144）。ブラウザの中だけで動く |
| 映像の扱い | 外へ送らない・保存しない。通信は部品（ライブラリとモデル）を読むためだけ |
| 部品の置き場 | `vendor/` があればそれを使う（通信なし）。なければ CDN から読む。`?cdn` で CDN に固定 |
| マス目 | 画面を `マスの大きさ`（既定 14px）で区切り、マスの中の4点で人物かを判定。明るさ7段の灰色のマス＋目地で描く |
| 外側から崩す | 上下左右のどれかが「人物でない／欠けている」マスだけを鳥が狙う。余った力は隣のマスへ回る（元ゲームの `impact()` と同じ） |
| 鳥の数 | 映っている時間 T で決まる。最初の5秒は1羽、30秒で約18羽、60秒で約60羽、90秒で約120羽（上限 120）。`鳥の増え方` で時間を伸び縮みさせる |
| 攻撃の強さ | 1 + T/40（1回つつけば1マス欠ける。時間がたつと隣のマスも欠ける）。羽数が増えるほど、つつく間隔も短くなる |
| 編隊 | 5羽から。V字 → 帯 → 球 を7秒ごとに入れ替える（元ゲームの `slot()` / `shape()`）。群れの中心は人物の頭の上を通る弧でゆっくり往復し、人物が動けば付いていく |
| 総攻撃 | 12羽を超えたら 16〜22 秒ごとに 2.2 秒。つつく間隔が短くなり、力が 1.8 倍。始まりの 0.16 秒だけ画面を反転（設定で切れる） |
| 払う | コマ間の明るさの差分を 8×8 画素の区画で見て、強く変わった所の近く（約 125px）の鳥を離す。動きが強いほど遠くへ長く（1〜3.6 秒）離れ、そのあと戻る |
| 歩く・出入り | 「払う」と見なさない。人物のマスの位置の中央値が速く動いている間は、払いの判定を止める（鳥は追い続ける）。中央値は腕を振っても動かない |
| 欠けの戻り | 既定 4 秒（±20%）。戻る直前の 0.35 秒でふっと現れる。欠けは画面の位置に付く（体には付いていかない） |
| A＝部屋の背景 | 人のいない所だけを、毎コマ少しずつ映像で上書きして「背景の板」をためる。欠けた所にはその板が見える。撮る操作は要らない（`R` で撮り直し）。まだ板がない所は、まわりの背景をぼかして延ばした色で埋める |
| B＝草木 | 欠けた所に苔・茎・葉・小さな花が 1 秒ほどで育ち、戻る直前にしおれる。草木だけ色が付く（白黒の中で自然だけが色を持つ） |
| 色 | 既定は白黒。`N` で 白黒 → ネガ → カラー。ネガは画面全体を反転する（草木の色も反転する） |
| 人がいない時 | 鳥は 1.2 秒待ってから上へ去る。T は 1 秒に 10 秒ぶん減る。全部去るとさえずりが鳴る。去りかけた時に人が戻れば、鳥は引き返す |
| 複数人 | まとめて1つの人物として扱う。鳥は自分に近いマスを狙うので、近い人を攻める |
| 音 | 元ゲームの風・羽音・鳴き声・さえずり。最初のクリックかキーで鳴り始める（ブラウザの決まり） |
| 画面の文字 | 作品としての文字は入れていない（「あなたも塔の側だ」をどう伝えるかは未決） |

### キー
`H` 設定　`F` 全画面　`A` / `B` 欠けた所　`N` 色　`G` 粒子と傷　`M` 音　`R` 背景の撮り直し　`0` 鳥をやり直す　`T` 合成の人影　`D` 動きの検出を表示

設定（`H`）：カメラ、マスの大きさ、鳥の増え方、鳥の上限、鳥の大きさ、欠けが戻るまで、欠けた所 A/B、色、総攻撃の反転、払う感度、粒子と傷、鏡像、音、輪郭のしきい値、描画の細かさ、動きの検出の表示、輪郭の反転（確認用）、合成の人影。上に毎秒のコマ数などを出す。設定は localStorage `birdsreclaim.mirror.v1` に残る（合成の人影だけは残さない）。

### 展示の前に要ること
1. 部品のローカル化：通信のある所で `./get_vendor.sh` を1回。`vendor/` は 30MB あり、いまはコミットしていない（`.gitignore`）。リポジトリに入れるかはユーザーが決める。
2. `node server.js` で `http://localhost:4182` を開く（`localhost` ならカメラの許可が残る）。`file://` は毎回たずねられる。
3. 音は最初のクリックかキーが要る。無人で始めるなら Chrome の起動オプションで外せるはず［要確認］。
4. 総攻撃の反転は光の点滅になる。0.16 秒を 16 秒以上の間隔で1回なので弱いが、会場の注意書きは考える。
5. モデルの URL が `latest` で、版が固定されていない。`vendor/` に置けば固定される。

### 途中で直したこと
- 最初の1羽がつついても欠けなかった（力 0.6、マスの強度 1）。力を 1 から始め、羽数が少ないうちはこまめにつつくようにした。
- 歩いて出ていくだけで 48 羽中 47 羽が逃げた。体ごとの移動を払いと見なさないようにした。重心で測ると大きく手を振った時も歩行と誤認したので、中央値に替えた。
- 去りかけた鳥がいる時に人が戻ると、1羽余分に増えた。数える前に引き返させるようにした。
- 人物のまわりに黒い縁取りが出た（背景の板がまだ無い所）。まわりの背景をぼかして延ばした色で埋めた。
- 草木が、人物が動いたあとの空中に残った。人物の内側の欠けにだけ生やすようにした。
- 行の途中に `//` の説明を書き、後ろの処理を消してスクリプト全体が止まった（元ゲームの LOG にある失敗と同じ）。直したあと、`node --check` と、同種の行の機械的な洗い直しをした。

## 2026-11-11 試作 v0.1：感想を受けた調整、草木の強化、PC・スマホ対応、公開（ユーザー指示）

### ユーザーの感想（本物のカメラ、Chrome）
- 払う：頭や体が動くと鳥が離れる。手で払っても離れるが、少し少ない。もっと大きく動いてもよい。
- 鳥：もっと大きくてもよいかもしれないが、大きいと野暮かもしれない。試したい。増える速さはもっと速くてよい。
- 色・コマ数・感度はよさそう。マスはもっと細かくてもよいかもしれない。いくつか試したい。
- B（草木）の絵がまだ思い浮かばないので見たい。
- PC とスマホの両方に対応し、リンクを作って GitHub に上げたい。

## 2026-11-11 試作 v0.8：奥行き（手前を飛ぶ鳥）（ユーザーの案。議論のあと「試作を」）

### ユーザーの案
- 鳥の立体的な演出。たとえば、手前から奥へ飛んでいく鳥が人に向かう。一部でよい。

### 議論で伝えたこと
- 画面は平面のまま。大きさ・ぼけ・濃さ・速さ・重なりで奥行きに見せる。
- カメラ1台なので本当の奥行きは分からない。人物は1枚の板として扱う。
- 心配：鳥は真上から見た形なので、拡大すると切り絵に見える恐れ。大きい鳥が野暮に見える恐れ（ユーザーが前に気にしていた点）。
- 案 A（手前から飛び込む）、B（払うと手前へ逃げる）、C（人物の後ろを回る）。A と B を先に試作する。

### 作り
| 項目 | 内容 |
|---|---|
| 奥行きの値 | 鳥ごとに `z`（大きさの倍率。1＝人物と同じ奥、大きいほど手前。最大 3.2〜5.8） |
| 手前の鳥の描き方 | 大きく、薄く（倍率が上がるほど透ける）、輪郭をぼかす。ぼかしは、少しずつずらして 7 回重ね描きする（ぼかしの命令は端末によって使えないため）。淡い縁取りは付けない。ほかの鳥より後に描く |
| A 手前から飛び込む | 最初の1羽と、あとから来る鳥の1割。画面の下の端か左右の端の下寄りから、大きな影として現れ、0.7〜1.1 秒で縮みながら群れの所へ来る |
| A′ 総攻撃の前触れ | 総攻撃の 1.3 秒前に、群れの1割（最大 16 羽）が手前へ大きくなりながら画面の外へ消え、総攻撃の始まりに手前から飛び込んで、すぐつつく |
| B 払うと手前へ逃げる | 強く払われた鳥の3割が、払われた向きへ大きくなりながら画面の外へ抜け、0.8〜3 秒して手前から戻る |
