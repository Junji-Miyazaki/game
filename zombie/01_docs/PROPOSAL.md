## 0. 結論（v0：ゲート型の案）

- **推す型：A「数字ゲート × 群れ撃ち」**。兵士の隊列が道を進み、数字のゲート（+10、×2 など）で人数を増やして、迫るゾンビの大群を撃つ型。
- **人型の造形の懸念**：個体を大きく、リアルに見せるのは難しい。ただ、この型は小さな人型を何百体も見せる遊びなので、輪郭と動きの癖さえ立てば十分に「ゾンビの群れ」に見える。そこで、試作の最初に「造形テスト」（§4.1）を入れ、見た目を先に確かめる。
- **既存の `mobile_game_zombie/`（と `mobile_game_zombie2/`・`game_zombie/`）**：テーマは同じだが型が違う（C 寄りの縦シューター）。参考にはするが、作り直しはしない。

## 1. 解釈：広告でよく見る「ゾンビもの」の型

| 型 | 一言で |
|---|---|
| **A 数字ゲート × 群れ撃ち** | 道を走る兵士の群れが +10 / ×2 / −5 のゲートを選んで増え、正面から来るゾンビの大群を撃ち倒す。 |
| B 防壁・レーン防衛 | 壁やバリケードの手前で、押し寄せるゾンビの波を止める。兵や砲台を置いて強くする。 |
| C 見下ろしサバイバー | 1 人で大群の中を逃げ回る。撃つのは自動で、拾った経験値で武器が育つ。 |
| D 救出パズル | ピンを抜く、道をつなぐなどして、人をゾンビから逃がす。1 画面の謎解き。 |

**A を推す理由**
1. 「広告のゾンビのやつ」と聞いて多くの人が思い浮かべるのは、数字ゲートを通るたびに群れがふくらみ、ゾンビの大群とぶつかる絵である。数字が目で見えて増え、結果が一瞬でわかるため、動画広告で最も目立つ。
2. 知人の言い方が、題名ではなく「広告で出てくるやつ」である。つまり広告の絵そのものを遊びたい可能性が高い。
3. B と C は広告でも見るが、「ゾンビ」より「タワーディフェンス」「サバイバー」として覚えられていることが多い（根拠は筆者の印象で、統計はない［要確認］）。

**広告と中身の違い**：この型の広告は、実際には街づくりや戦略ゲームの宣伝であることが多い。広告に出る「ゲートで増えて撃つ」場面は、アプリの中ではおまけ程度か、まったく無いこともある。そのため、知人が「やりたい」のに遊べなかったのは、広告のあの部分そのものである可能性が高い。今回はそこだけを、ちゃんと遊べる形で作る。

**知人に確かめたい質問**
1. 「数字のゲートをくぐると人が増えていくやつ？それとも壁を守るやつ？」（可能なら広告の画面を 1 枚見せてもらう）
2. 「1 回 1 分くらいでスカッと終わる方がいい？それとも育てて長く遊びたい？」

## 2. 提案（型 A のオリジナル作品）

### 2.1 名前の案
- **NIGHT RUN ×（ナイトラン・カケル）**：夜の道を走り、人数を掛ける。第一候補。
- **増隊（ぞうたい）**：短く、和風で覚えやすい。
- **DAWN LINE**：夜明けの地点まで群れを届ける。

※ 実在タイトルとの重複は、名前を決める時点で検索して確かめる［要確認］。

### 2.2 核になる遊び（30 秒でわかる気持ちよさ）
- 親指で左右に動かすだけ。兵士は自動で前進し、自動で撃つ。
- ゲートを通るたびに、人数の数字と隊列が「ボン」とふくらむ。×2 を引いたときの増え方が一番の快感になる。
- その群れでゾンビの波を正面から削り切る。人数＝火力＝体力なので、選んだゲートの結果がそのまま戦闘に出る。

**独自のひとひねり（案、要判断）：撃つとゲートの数字が育つ**
- ゲートも弾を受ける。−10 のゲートも撃ち続ければ −5、0、+5 と良くなる。
- そのため「近くの小さな +5 を取るか、遠くの −10 を撃って育ててから取るか」という判断が、片手のままで生まれる。
- ゲートを撃つ間はゾンビに弾が行かない。この取り合いで緊張を作る。

### 2.3 1 プレイの流れ（約 60〜90 秒）
1. 開始：兵士 10 人で道に立つ。
2. 区間 1〜3：ゲートの組（左右に 2 枚）を選びながら進む。区間ごとにゾンビの小さな群れが来る。
3. 中間：大きな群れ（波）が来る。人数が足りないと、ここで削られる。
4. 終点：ボス（大型ゾンビ）か、バリケードの奥の巣を壊す。
5. 結果：残った人数がコインになる。強化して次のステージへ。

### 2.4 成長・やり込みの軸
- **強化（コインで購入）**：開始人数、1 人の連射速度、弾の威力。最初はこの 3 つに絞る。
- **ステージ**：1→30。後ろのステージほど、負のゲートと大きな群れが増える。
- **記録**：各ステージの最多の生き残り人数（★1〜3）。
- 後で足す候補：兵種（散弾兵・狙撃兵）、世界ランキング（LANDER の中継の仕組みを流用できる［要確認］）。

### 2.5 操作（スマホ縦持ち・片手）
- 画面のどこでも、押したまま左右に引くと、隊列がその向きへ動く。指の動きにそのまま隊列が付いてくる（相対移動）。
- 他の操作は無い。強化画面とメニューは、親指の届く下半分に置く。
- PC では、マウスのドラッグか ←→ キーで同じ動きにする。

### 2.6 見た目と音の方向
- **見た目**：夜の一本道を、少し上から奥へ見下ろす（奥ほど小さく描く疑似 3D）。兵士はシアンに光るシルエット、ゾンビはくすんだ緑の体に赤い目。ゲートは +＝青、−＝赤、×＝金で光らせる。METEOR や LANDER のネオン調と揃える。
- **音**：Web Audio で合成する。発砲は短いノイズ。人数が増えるとき、和音が人数に応じて上がっていく（増えた量が耳でもわかる）。ゾンビの波は低い唸りが近づいてくる音にする。

## 3. 人型の造形と動きについて（ご指摘への答え）

**結論：ご懸念はもっともで、半分当たっている。** 既存の試作でも、ゾンビは四角形の組み合わせで描かれており、人にもゾンビにも見えにくかった。一方で、この型は見せ方を工夫すれば避けられる。

**難しい点**
- 画面に大きく映る人型を、自然に歩かせること（膝や肩の関節、重心の移動）。
- 表情や、撃たれて崩れ落ちる物理的な動き（ラグドール）。

**この型で避けられる理由**
- 画面に出る 1 体は小さい（画面の高さの約 1/30、スマホで 20px 前後）。
- 何百体も並ぶので、1 体の細かさより、群れとしての輪郭と動きの揃い方・ばらつき方で「ゾンビらしさ」が伝わる。

**作り方（2D Canvas、画像素材なし）**
1. **部品と骨格で動かす**：頭・胴・腕 2・脚 2 を、関節の角度で動かす（手続きアニメ）。
2. **ゾンビらしさを動きの癖で出す**：
   - 腕を前に突き出す。
   - 前かがみで、頭が傾いて揺れる。
   - 片脚を引きずり、歩幅が左右でそろわない。
   - 1 体ずつ歩く速さと位相をずらし、行進しているようには見せない。
   - 兵士は逆に、背筋を伸ばして足並みをそろえる。これでゾンビとの対比がはっきりする。
3. **軽くする**：1 種類あたり 8 コマを最初に裏の画面へ描いておき、あとは貼るだけにする。数百体でも重くならない。
4. **やられ方**：ラグドールは作らない。体が部品と光の粒に弾けて消える。派手で、作るのも簡単。
5. **大きく映るボスにだけ手間をかける**：関節を増やし、「溜める→叩きつける」を大げさに動かす。

**別の手段**
- 手描きのドット絵や、画像のスプライトを使う。`mobile_game_zombie/images/` に `player.png` と `bossZombie.png` があるが、既存の試作では使われていない。流用するかはユーザーが決める。
- three.js による低ポリゴンの 3D（広告の多くはこれに近い）。見た目は近づくが重く、作る手間も大きい。2D で足りなかったときの次の手にとっておく。

→ これを最初の「造形テスト」で確かめる（§4.1 の段階 0）。見た目に納得できなければ、ゲーム部分には進まない。

### 4.1 最初に作る最小の試作
**段階 0：造形テスト（1 ページ）**
- ゾンビと兵士の歩く動きを、大・中・小の 3 つの大きさで並べる。
- ゾンビ 300 体と兵士 200 体を同時に歩かせ、fps を表示する。
- 確認すること：「ゾンビに見えるか」「群れとして気持ち悪く見えるか」「スマホで 60fps 近く出るか」。

**段階 1：1 ステージ遊べる最小版（段階 0 の OK 後）**
- 入れるもの：左右ドラッグ、自動前進・自動射撃、ゲート 4 組、小さな群れ 2 つと大きな波 1 つ、ボス、結果画面、やり直し。
- 入れないもの：強化、保存、ステージ選択、ランキング。音は発砲・ゲート・撃破の 3 つだけ。
- 完了の条件：スマホで 1 ステージを通して遊べる。ゲートの選び方で勝ち負けが変わる。

### 4.2 画面構成（縦 9:16、論理解像度 360×640 を拡大表示）
```

│ STAGE 3   ●128 │ ← 上：ステージと人数（大きく）
│     ╲  道  ╱     │
```

| 項目 | 初期値 |

| 道の幅 | 8m（ゲート 2 枚が並ぶ幅） |

### 4.4 ステージ構成の骨子
- **1〜3（教える）**：正のゲートだけ。群れは小さい。×2 の気持ちよさを覚えてもらう。
- **4〜8**：負のゲートが混ざる。「撃って育てる」を教える（−5 のゲートを撃てば +なる配置）。
- **9〜15**：太ったゾンビ。左右から群れが来る区間。
- **16〜30**：ゲートの直後に大きな波。÷2 のわな。5 の倍数のステージで大型ボス。
- ステージは、手作りの配置表（JSON 風の配列）で作る。乱数で並べるのは、後で無限モードを作る場合だけにする。

### 4.5 技術の方針
- **単一の HTML**（`zombie/02_src/index.html`）に Canvas 2D と Web Audio。外部のライブラリは使わない。GitHub Pages にそのまま置く。
- **疑似 3D**：道の上の位置（x, z）を持ち、z に応じて縮小して画面に描く。奥から手前へ描く。
- **重さ対策**：人型は最初に裏の画面へ描いて貼る。当たり判定は z を区切った格子で調べる。物体は使い回す（オブジェクトプール）。
- **保存**：コインと強化は localStorage に保存する（段階 2 以降）。
- **テスト**：`04_tests/` に、ゲートの計算、接触による相殺、ボスの HP の式を、Node で確かめる小さなテストを置く。
- **フォルダ**：`00_log/` `01_docs/` `02_src/` `03_assets/` `04_tests/`。
